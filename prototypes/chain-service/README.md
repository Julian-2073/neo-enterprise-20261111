# NEO 直营门店协作原型

双击 `NEO直营门店协作原型.html` 即可离线体验。所有样式、图标和逻辑已包含在单个文件中，无需安装依赖、登录或连接网络。

## 演示内容

模拟品牌「澄禾护理」的湖滨店下午空闲、晚间拥挤。总部 Agent 发现时段结构问题，门店 Agent 核查员工、护理间和耗材，双方协作安排一次小范围顾客跟进，并在服务完成后复盘。

五个页面：

1. **总部今日经营**：三家门店总览、时段占用和优先经营事项。
2. **总部经营事项**：问题依据、方案、执行验收和复盘。
3. **门店今日**：当日经营、服务安排、总部任务及本店优先动作。
4. **门店行动详情**：现场核查、资源支持、任务接收、培训与执行回传。
5. **门店顾客**：筛选、顾客档案、联系草稿、模拟回应及预约。

## 建议演示顺序

沿顶部阶段条和 Agent 卡片中的「下一步」操作：

1. 总部进入经营事项，查看依据并发起门店核查。
2. 切换门店，核实人员、护理间和耗材并提交现场情况。
3. 总部安排两份耗材支持，确认方案并下发任务。
4. 门店接收任务、确认耗材到位、阅读执行规则。
5. 进入顾客页，检查三位顾客的联系名单和草稿；确认后载入模拟回应。
6. 分别为林女士确认 14:00、陈女士确认 15:00 预约；同一时段不可重复占用。
7. 门店提交执行记录，总部验收，再进入模拟观察日。
8. 查看两人到店、服务金额 536 元及商品金额 89 元；记录继续验证或暂停调整的决定。

已有预约、近期联系和不接受营销联系的三位顾客会被排除。联系人、回应、预约、实际到店和复盘有独立状态，不能跳过验收直接宣称经营改善。

## 原型边界

- 全部经营与顾客数据均为模拟。Agent 的建议、回答和回应为预设场景，没有调用真实模型。
- 不连接 CRM、预约、支付、消息渠道或任何真实系统，不会向顾客发送消息。
- 顾客页用于演示日常跟进；未来通过接口接入既有客户、预约与交易系统。本版没有实现连接器、支付、卡项核销或完整 CRM。
- 总部侧聚焦新增连锁协作流程。NEO 其他现有功能仍在原应用，本独立原型没有复制全部现有模块。
- 切换总部与门店时共享当前演示进度，刷新后尝试从本浏览器恢复。浏览器禁止本地存储时页面会提示。不同文件副本、来源或浏览器的进度互不共享；不支持多人实时协同。
- 顶部「重置演示」只清除这份原型的演示进度，确认后恢复初始状态。
- 完成服务的结果不能证明活动带来因果增量，复盘明确保留这一限制。
- `mobile-preview.html` 提供 390 × 844 的手机尺寸预览；主页面本身支持响应式布局。

## 修改与验证

源码为 `template.html`、`styles.css`、`app.js` 和 `model.cjs`。在 NEO 仓库已有依赖环境中运行：

```sh
node prototypes/chain-service/build.mjs
node --test prototypes/chain-service/verify.mjs
```

构建复用已有 React 与 Phosphor Icons，仅用于生成内嵌图标；运行原型无需这些依赖。Phosphor Icons 的 MIT 许可已内嵌在 HTML 中。

自动检查覆盖完整闭环、前置条件、重复联系、预约冲突、执行与效果区分、刷新恢复、重置及文本安全。浏览器验证记录截图位于 `output/playwright/chain-service/`。

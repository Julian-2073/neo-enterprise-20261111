## 1. 先读这个：范围与执行依据

### 1.1 本期要完成的内容

六个独立页面：

1. 经营首页：老板入口，当前经营 + 市场机会 + 钱 + 人货场摘要 + 未来预览。
2. 经营分析 · 人：4A 转化链、四线经营脉搏、钱的组成、转化纠察对话。
3. 经营分析 · 货：三类商品、供应链与库存、商品表、供应脉搏、库存资金、供需纠察对话。
4. 经营分析 · 场：市场变化、竞品、渠道与商品角色矩阵、投入结构、市场观察对话。
5. 经营联动总览：同一时间轴上的人货场证据、三智能体协作、联合研判。
6. 未来与决策中心：基线预测、Jev 判断摘要、方案比较、行动编排对话、行动生命周期。

**实现真实的网页组件与本地演示交互。不能把截图铺在网页上充当整个界面。**

本期不开发后端、数据库、真实模型调用、真实企业数据接入、实际投放/采购/任务下发、真实权限或消息推送。所有经营数据、智能体回复、预测和行动状态都由本地演示数据驱动。

经营周报此前只讨论过结构，还没有确认图片。本次不做完整周报页。导航可以保留“经营周报”，标记“规划中”；点击打开简短提示，不能跳到空白页面或假装已能推送。

## 3. 视觉与排版规范

### 3.1 已确认风格

- 苹果式简洁感：白色主底、深色文字、少量蓝色操作、细浅边框、充分留白。
- 展示经营判断的工作台，图表使用干净线条与轻网格。
- 避免深色股票终端、霓虹光效、复杂渐变、仪表盘堆砌和大面积红绿涨跌色。
- 卡片圆角统一；按钮、输入框、标签的尺寸和状态统一。
- 单页图用于参考布局与信息层级，不应机械复制生成图片中的错字或模糊文字。

### 3.2 可直接采用的视觉变量

以下为落地建议，可与既有主题等值适配：

| 项目 | 建议 |
|---|---|
| 主背景 | #FFFFFF；分组底色 #F6F9FD |
| 主文字 | #101828 或接近的深蓝黑 |
| 次文字 | #667085；说明文字需保持可读对比 |
| 主操作蓝 | #007AFF / #006BFF |
| 边框 | #E1EAF5 |

| 青绿 | #12B8A6，表示某条正常数据序列 |

### 3.3 响应式

- 1440px 桌面优先：主体分析 + 右侧智能体，建议比例约 68:32。
- 1280px：主体不挤压到标签无法辨认；可略缩间距。
- 窄于约 1100px：智能体区域移到分析区下方，保持其独立输入区。
- 390px 移动端基础可用：指标两列或单列、卡片顺序堆叠；表格和矩阵在自身容器横向滚动。
- 首页保留自然向下滚动的长页。不要把其全部内容压缩成一个桌面屏幕。
- 不要把全页做成仅有固定高度、内部滚动的巨大面板；聊天记录区域可以单独滚动。
- 图表外层响应宽度；关键标签、异常区域、输入框和主要按钮不裁切。

## 4. 统一演示数据与必须修正的口径

数据文件为 **demo-data.json**。它是前端 fixture，不是真实企业记录。优先由这一份数据派生所有显示，不能在每个页面各硬编码一套金额。

### 4.1 人的经营结果：R1 / 抖音 / 近 8 周

- A1 看过：82,400
- A2 兴趣：19,600
- A3 意向：2,480
- A4 有效成交：310
- A1→A2：19,600 ÷ 82,400 = 23.8%
- A2→A3：2,480 ÷ 19,600 = 12.7%
- A3→A4：310 ÷ 2,480 = 12.5%
- 前一等长 8 周 A3→A4 比值：15.7%（独立演示基准）。
- 变化：12.5% − 15.7% = **下降 3.2 个百分点**，不要写成下降 3.2%。

这是演示阶段人数比值；正式上线是否可称去重客户转化，需要真实客户/同一批人统计定义。本期保留“转化率”界面词，并在信息提示注明“演示阶段比值，正式口径待接真实数据确认”。不能从聚合人数推断确切个人流失。

当前 8 周 A3→A4 的 12.5% 不是第 8 周的单周转化率。单周比值使用对应周 A4/A3 算出，不把 12.5% 写死在周曲线的终点。

金额：

- 净成交额：¥589,000
- 商品 / 平台 / 履约可变成本：¥348,000
- 投放费用：¥88,000
- 贡献毛利：¥153,000
- 恒等式：589,000 = 348,000 + 88,000 + 153,000。
- 分别占净成交额 59.1%、14.9%、26.0%。

贡献毛利是这里给定可变成本与投放后的模拟贡献，不是企业净利润，也不是现金余额。

## 5. 六个页面实施要求

### 5.1 经营首页

参考 images/01-首页.png。

从上到下：

- 顶部建议行动“生成联动核查清单”打开本地草案，区分负责人、证据、待核查和截止日。
- 底部联合研判仍保留：已知事实 / 待核查 / 优先动作。

### 5.6 未来与决策中心

参考 images/06-未来与决策中心.png。

- 顶部流程：基线预测 → 方案推演 → 行动决策。
- 基线图：历史实线、预测起点、未来虚线、模拟区间。区间说明“演示区间，未用真实数据回测”。
- Jev 摘要：优先级高 / 主要待核查约束供给 / 证据充分性中 / 需要人工复核。仅为模拟分类与路由。
- 三张可选方案：A保持现状，B先核查并保供，C加大投放。
- 选择方案更新高亮、相关假设、右侧草案上下文。B的情景增量只能标“情景估计”，不承诺真实效果。
- 右侧行动编排对话；顶部“生成行动草案”只生成草案，不进入实际执行。
- “调整预算 / 比较方案”打开参数或比较抽屉。
- 下方动作生命周期：草案 → 人工确认 → 执行 → 观察与复盘；点击查看本地状态说明。
- 允许演示确认草案，但按钮明确“确认演示草案”，提示“已保存到本地演示，不会下发任务”。

情景计算采用本地预设组合：预算“保持/增加20%”，到货“按原计划/提前一周”，匹配 demo-data.json 中的演示结果。任意金额/日期先解析为假设并让用户确认；若没有对应样例，显示“此组合暂无演示结果”，不编造实时计算。每个情景展示所用预算、到货日期、区间性质与版本。

## 6. 智能体互动区域：统一组件与行为

这是本轮最重要的更新。五页共用同一套可配置组件，不要各做一个风格完全不同的聊天框。

### 6.1 组件结构

从上到下：

1. 标题、头像、小状态。
2. **一个小型建议行动按钮**：浅蓝底或描边、高约36px、短句，保持轻量。
3. 对话记录：智能体左、用户右；简短内容；证据链接/草案卡可以嵌在回复内。
4. 可选追问 chips：一般 2 条。
5. **输入框**：多行、清晰占位文字、发送按钮；联动支持智能体选择/@。
6. 一行轻量说明：模拟对话 / 数据可追溯 / 行动需人工确认。

智能体区不能重新变回长篇静态“发现/证据/原因”清单。主分析负责事实展示，对话负责解释、追问、补充上下文与下一步动作。

### 6.2 五处配置

| 页面 | 建议行动 | 输入提示 | 典型追问 |
|---|---|---|---|
| 人 | 核查转化断点 | 继续追问，或补充你的经营判断… | 哪些人群流失最多？ |
| 货 | 核查异常 SKU | 询问库存、补货或调拨方案… | 能否先调拨？ |
| 场 | 核查渠道证据 | 追问市场变化，或补充竞品信息… | 是竞品还是承接问题？ |
| 联动 | 生成联动核查清单 | 向三位智能体追问，或@指定智能体… | 先查哪一项？ |
| 未来 | 生成行动草案 | 输入补货时间、预算或你的决策约束… | 补货提前一周怎么调整？ |

### 6.3 交互细节

- Enter 发送、Shift+Enter 换行；中文输入法组合输入时不触发发送。
- 空白内容不能发送；输入最多 1000 字并有提示。
- 发送后立即保留用户消息，短暂模拟“正在整理证据”，再返回本地演示回复。
- 消息增长后滚到最新消息；用户主动回看时不强制拉走，出现“有新回复”提示。
- 证据链接打开对应抽屉/页面，用户信息不会丢失。
- chip 点击直接发送对应预设问题，走同一消息流程。
- 附件 icon 要么实现本地文件选择，仅显示文件名且标“演示附件，不上传”；要么隐藏。不得只画一个不能用的控件。
- 发送按钮必须有正常/禁用状态；输入框聚焦态可见。
- 页内会话维持在本地；切换标签或返回不会覆盖其他页会话。
- 初始示例对话可由 fixture 装载；提供“重置演示”恢复初始消息和草案。

### 6.4 本地回复策略

无需调用大模型。基于 agentId + issueId + 页面切片 + 少量意图匹配：

- 人：渠道/人群/流失 → 阶段比值与切片证据；库存 → 引导联查货。
- 货：库存/缺货/SKU → 异常清单；在途/到货 → 10.06与180件；调拨 → 可用量与成本待核查。
- 场：竞品/促销 → 模拟事件；原因 → 同期关联，需结合人货证据；渠道 → 对应矩阵。
- 联动：先查/优先 → 库存与客服承接，然后价格和渠道；指定对象 → 该智能体回复。
- 未来：预算/补货/提前 → 打开假设编辑卡；方案 → 比较草案；确认 → 要求点击确认演示草案。
- 无匹配：如实回复“当前演示未覆盖这类问题，可查看已有证据或补充条件”，附2个相关追问。不要伪造经营数据。

### 6.5 人工补充信息

用户文字只是新线索，不能自动变成已核实事实。将“客服最近延迟”“预计提前到货”等标为“用户补充 · 待核实”。只有在未来参数卡确认后，作为新的演示情景假设影响预设情景选择；不可改写历史成交和库存数据。

## 7. 数据、组件与状态组织建议

优先适配现有结构，建议分成：

- 页面：Home / People / Goods / Market / Overview / Future。
- 公用：AppShell、ScopeFilters、MoneyStrip、MetricCard、EvidenceDrawer、OpportunityDrawer。
- 图表：FourStagePulse、SupplyComplianceChart、MarketTimeline、ChannelRoleMatrix、ForecastPreview。
- 智能体：AgentPanel、ChatMessage、ChatComposer、SuggestedAction、AgentSelector、DraftPreview。
- 数据：演示原始序列、作用范围、派生计算、异常区间、消息预设、情景假设。
- 状态：当前议题、角色视角、局部筛选、会话、草案、选中情景。

数据类型至少表达：

- metric：值、单位、统计窗口、切片、口径说明、模拟标记。
- evidence：事实/规则/外部观察/预测/情景的类型、来源类型、发生时间、范围、关联页面。
- chatMessage：id、role、agentId、content、关联证据/草案、模拟标记。
- draft：目标、证据、假设、负责人、预算、截止日、观察指标、状态。
- scenario：基线版本、预算档、到货假设、周度中值、总量区间、性质标签。

所有比例、金额组成与相对指数由函数计算，避免展示格式直接参与计算。

异常规则本地可解释：

- 人：最近两周 A3分别较前周上升且A4分别下降，标第7–8周为“趋势错位”；总周期比值较前基准下降另行计算。
- 货：主力品达标率连续两周低于80%，标对应区间。
- 场：演示矩阵中抖音×主力格由 fixture 标成需核查；外部事件重合只表示关联。
- 联动：引用上述已定义区间和证据，不再另造因果评分。

建议本地存储仅保存演示会话/草案/视角；加版本前缀。数据重置只删除本演示的键，不清空其他网站存储。

## 8. 实施顺序

1. 仓库检查、路由与公用布局、视觉变量、mock 数据和口径修正。
2. 首页 + 人页 + 共用智能体组件，先把分析与对话的一条完整跳转链做通。
3. 货页 + 场页，复用聊天组件、证据抽屉与派生数据。
4. 联动页，共享时间轴与多智能体会话选择。
5. 未来页，基线/情景/草案/人工确认本地闭环。
6. 响应式、键盘交互、数据核对、图片对照、运行与构建验证。
7. 汇报实际完成页面、启动方式、截图和已知限制。

不需要每做一个页面就停下来请求确认。遇到可逆的实现选择按现有代码习惯推进；只有目标仓库缺失、关键素材打不开或用户约束冲突才说明阻塞。

## 9. 验收标准

### 9.1 页面与视觉

- 六页可进入和刷新；顶部/二级导航状态正确。
- 首页市场机会在右上；人货场往下排列；未来预览在底部。
- 人页四条线同面板；货页三类达标率同图；场页矩阵为主视图。
- 联动三层时间对齐；未来有清晰历史/预测分隔与不确定区间。
- 五个智能体都有上方小建议按钮、对话、下方输入框；输入与发送真实可用。
- 1440/1280桌面及390移动基础布局无关键内容裁切。
- 图片和网页差异以口径纠正、响应式为限，不能凭技术便利改成另一套页面。

### 9.2 数据与状态

- 8周A4合计310；4A各期合计匹配；转化比值23.8/12.7/12.5%，差3.2个百分点。
- 589,000金额组成之和正确；库存总计1,260,000；渠道投入总计210,000。

### 9.3 演示操作路径

路径A：进入首页 → 点经营议题 → 联动总览 → 看人页异常 → 输入“哪些人群流失最多” → 查看证据 → 联查货的R1详情。

路径B：货页 → 点核查异常SKU → 看42件/80件安全线/180件在途 → 问能否调拨 → 出现待核查建议。

路径C：场页点抖音×主力 → 查看来源与事件 → 追问原因 → 得到关联而非因果结论 → 返回联动。

路径D：未来页 → 选择B → 输入补货提前一周 → 编辑确认情景假设 → 比较方案 → 生成草案 → 确认演示草案 → 本地状态更新。

路径E：会话输入空白不发送；中文输入法不误发；返回页面会话仍在；重置后恢复初始。

### 9.4 验证与交付

按仓库既有检查方式运行可用的构建、类型/静态检查。对派生金额、比值、归一化、异常判定和路由上下文做必要的验证；不用为了截图布局写大量镜像测试。

至少保留六页桌面截图，另选首页和聊天输入各一份移动端截图。最终交付说明写：启动命令、完成页面、模拟功能、未接能力、口径修正、检查结果。不要把静态演示描述为智能体已经部署或业务动作已执行。

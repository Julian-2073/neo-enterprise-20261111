## 经营表达规则

老板页面先说经营现象、影响和下一步，再提供数字与证据。标题一句、原因一句、建议一项；专业卡片各自说本专业判断。事实、待核原因、条件预测分别表述，不用同期变化证明因果。

| 原表达 | 经营表达 | 使用条件 |
| --- | --- | --- |
| R1 安全线缺口 | 家用划船机（R1）的可售库存低于已设定备货目标 | 名称来自商品资料；目标存在但尚需确认时必须说明 |
| 行为订单背离 | 客户关注与订单走势不同，原因还需核实 | 两项来自同一范围、可比期间；行为仍按次，不写客户人数 |
| content 口径待核 | 渠道名称待确认；这笔费用尚未对应具体商品或成交 | 没有确定主数据时不猜成“内容渠道” |
| 必须先理解业务结构并查询经营证据 | 本次分析未完成资料核对，已完成判断仍保留，可恢复调查 | 系统自动补查，老板不承担内部工具操作 |
| 430.9286 人 | 预计约 431 件 | 原结果单位为件；计算明细保留小数，不改成实际出库记录 |

统一呈现规则在 `lib/business-presentation.ts`：名称、范围、资料性质、调查失败和历史回答有效性。金额按计算单位换算，不通过关键词改数字；日期使用经营截至与保存时间，分别说明。原始来源、输入假设、引用、版本在详情中保留。

旧输出不覆盖原件；显示层仅转换已定义的术语、资料性质和明确标注的计算参数，保留事实数字、成立条件和不确定性，不再用统一的“待复核”摘要遮住整条回答。单独出现“万元”不判定错误，也不猜测或修正历史回答中的金额。原始回答、引用和计算输入可展开回读。Markdown 强调使用显示组件解析。Python 的名称、工具范围及输出校验修改属于待整合内容，本轮未重启现有 Python 服务，也未验收修改后的真实模型回答。

## 本轮交付与验证边界

- REPORT-01：统一两种决策的方案回读，严格核对企业、资料性质、快照和对象版本；父记录缺失只影响当前卡片。
- OWNER-02：历史预测版本、同基线方案和选择理由，可通过链接刷新回读。
- SCOPE-03：企业、商品、渠道、期间和已保存资料切换，各页保持同一范围。
- EVIDENCE-04：商品库存、渠道货盘、单周指标证据按所点对象和时间查询固定事实集合。
- BIZ-01/02：名称、范围、异常与历史回答的显示规则已接入。BIZ-02 按下表转换已定义术语和明确的参数表达；没有重新生成或覆盖历史模型结论。真实模型重新生成后的业务表达质量尚待验证。
- DATA-03/04/05、Python 任务队列及预测引擎不在本轮收束范围。客户关联、正式供给目标与市场状态的模拟资料接入、完整模型链路由独立开发内容整合后再验收；本轮页面明确保留缺项。

普通和对象模型决策在 `/demo?page=weekly`、`/reports/weekly` 均可回读。M1 只显示自身 6 条库存记录、可售 68 件、在途 120 件、库存成本 21 万元；企业总库存成本 126 万元不变。历史基线与降价方案刷新后仍回读原结果。单周来源同时限定数据、指标和范围标题。390 像素视图的范围控件未横向溢出。

完整测试曾通过 89 项 Node 测试、构建及 20 项渲染测试；最后改动再次通过构建、类型检查、6 项局部证据测试和 20 项渲染测试，相关接口 29 项测试通过。执行命令、截图、文件清单与尚未完成项见 `outputs/business-alignment-2026-10-04/handoff.md`。

最终验证结果与代表截图在本轮输出目录中回读，不用工程测试代替真实客户、市场或预测效果证明。

## BIZ-02 经营表达细修

| 修改前 | 修改后 | 保留的依据与边界 |
| --- | --- | --- |
| R1 的“5个仓库/SKU库存低于安全线” | “有5处商品规格库存偏低，需核对备货目标” | “处”按仓库与商品规格组合计数，不是5种商品；逐仓明细说明计数单位。零可售、低于目标、缺目标分别处理 |
| M1 库存说明混入客户人数、退款规则 | 默认只显示库存共享渠道、覆盖日期与最新导入限制 | 全部原始限制仍在折叠详情；可售68、在途120、成本210,000.00元、6条来源不变 |
| 预算×1、价格×0.9、价格弹性-0.5 | 投放不变、降价10%；销量响应假设：价格提高1%时，订单需求约减少0.5%，尚未验证 | 原始参数、来源和输入确认状态保留；输入已确认不代表效果验证。百分比编辑仍提交相同倍数接口 |
| 数据性质demo、价格倍数0.9 | 合成演示数据、降价10% | 原金额、数量、日期、反证及限制保留，不通过显示规则修正模型事实错误 |
| 历史提问直接显示 proposedAssumptions、confirmed=true 等 | 默认折叠“原始提问（含计算参数）” | 原始提问逐字保留；普通业务提问继续直接显示 |

专用方案条件组件在提案、方案成立条件、行动选择与对象模型结果中共用。预算或价格不变时不展示无关响应系数；改变预算却未提供响应时，明确不能据此判断销量变化。调拨同时扣来源仓、到货前不计可售，仍按原始方案条件说明。

BIZ-02 仅修改主仓 TypeScript/UI、相关测试与文档，未修改 Python、数据库、迁移、凭证或服务。最终类型检查、构建、17项受影响测试、20项渲染测试和只读显示规则对账通过。浏览器首次回读已确认库存状态、M1来源及旧降价方案；随后浏览器控制连接超时并报告不可用，最后一次刷新、展开原始提问与最后术语细修后的页面回读尚未验证。库存截图只证明可见部分，不用它代替抽屉底部文字或刷新证据。

细修前副本在 `outputs/business-alignment-2026-10-04/biz-02/before/`，采用 `.rollback` 扩展名避免被 TypeScript 当作项目源码；`baseline-files.json` 记录对应路径与哈希。上一轮交接和清单在 `v1/` 保留。精确补丁与复验边界见最新交接。

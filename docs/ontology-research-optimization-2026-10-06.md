## 采用与调整

研究来源：`/Users/majun/Downloads/deep-research-report.md`。该文档是 RDF/OWL 工程指南，不是 Palantir Foundry 的部署方案。文中的安装命令和外部发布步骤仅作为资料阅读，未作为操作指令执行。

| 文档建议 | NEO 本轮落实 |
| --- | --- |
| 明确核心类、属性、关系和业务含义 | 默认保留 NEO 固定模型；增加自由类型创建表单、关系表单和属性约束面板 |
| 明确 Domain / Range、基数、正反向关系 | 展示源类型 → 目标类型、实际关联键、目标主键、基数和两端业务名称；支持多对多关联类型 |
| 稳定标识和序列化 | 按企业生成类型、属性、关系 IRI；下载完整配置包和 JSON-LD 词汇结构 |
| SHACL 风格的质量问题定位 | 回读 NEO 现有验证结果；展示等级、约束代码、类型、对象、源字段、目标属性和记录行；提供筛选、搜索、分页和修复入口 |
| 版本控制、变更前验证 | 草稿发布前展示类型、属性和关系差异，以及候选资料的质量结果；修改后禁用旧草稿的发布入口 |
| 图数据库、OWL 推理、SPARQL | 本轮未启用；继续采用 D1/Drizzle、R2 和已有受控查询及 Action，不迁移存储 |

Palantir 的 Ontology 把数据与业务对象、逻辑和动作连接起来，因此本轮延续 NEO 已有的业务操作层，而不是替换成一个单独的 RDF 数据库。[Palantir 官方概述](https://www.palantir.com/docs/foundry/ontology/overview)

文档“将父亲/父母关系设为传递关系即可推理祖父”的示例需要纠正：传递性得到的是同一个关系的闭包，不能把祖父直接当作父亲。W3C 示例使用祖先关系的传递性，或由两次父母关系形成祖父关系的属性链。NEO 本轮只执行明确配置的关联，不推断传递关系。[W3C OWL 2 Primer](https://www.w3.org/TR/owl2-primer/#Property_Chains)

质量面板借鉴了 SHACL 报告的“对象、路径、等级、约束与消息”表达方式，但实际验证由 NEO 验证器完成；没有声称已部署 SHACL 引擎或生成标准 SHACL 验证报告。[W3C SHACL 验证报告](https://www.w3.org/TR/shacl/#validation-report)

## 已实现的操作

1. 在 Ontology 页选择商品、SKU、库存等类型，查看属性、实际约束和值源规则；库存观测的安全库存非负规则与导入校验共用。
2. 新增自由业务类型。初始提供稳定 `id` 和业务 `name`；新增其他属性可经高级定义入口编辑并由后端校验。新类型不会自动获得 Agent 权限。
3. 使用关系表单配置两端类型、文本关联键、基数、正反向名称和说明；多对多关系声明中间关联类型及两端键。
4. 保存草稿后继续修改，发布按钮即失效，须重新保存。模块切换保留本页草稿，但数据接入仍读取已发布定义；企业、投影及定义切换清除草稿引用。
5. 发布预览显示具体变更及候选对象/关系数量；定义结构可以发布，资料有问题时须修正后才可构建有效投影。原投影和历史结果不重写。
6. 导入与投影错误能定位到属性和源字段。CSV 导入使用含表头的物理行号；投影中的主数据来源记录保留现有不含表头的记录行号，面板统一标为“源记录行”。
7. 质量面板每页 30 项，支持等级、类型及关键词组合筛选；主数据缺口可跳到导入入口，已存在对象的问题可进入对象详情。
8. 完整配置导出包含企业、定义、投影、数据性质和截止时间。JSON-LD 仅导出词汇结构，不包含对象实例、运行结果、历史可用性证明或推理结果；约束是 NEO 注释，不是完整 SHACL 模型。

同时修正：倍率为 0 时预览和实际转换不一致；安全库存错误在预览中缺少字段定位；历史投影映射表单仍可编辑；修改配置后旧草稿仍可发布；转换预览在配置变化后残留。

## 范围与后续

没有安装 Java、Protégé、GraphDB、Jena、OWL/SHACL 推理工具，没有新增数据库迁移或远端发布。当前结果证明建模、校验、版本发布和可视化操作可用，不证明真实企业资料完整或预测准确度提升。

业务建模的下一步建议由具体问题驱动，例如“某个 SKU 未来四周的到货与可售量是否支撑销量”。先确认对象、数据来源、时间可用性和关系覆盖，再用既有预测评估闭环验证；不要为追求图谱规模直接扩大推理范围。

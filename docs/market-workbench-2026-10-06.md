# 渠道与竞品工作台：原型对照与后端实现

原 demo 是展示基准，本次没有修改它的代码、样例数据、样式或布局。业务模式独立使用 LiveMarketPage，保留三张判断卡、渠道与货盘矩阵、变化观察、投入结构和右侧智能体的结构。

| 原 demo 功能 | 原业务页面缺口 | 本次实现 |
|---|---|---|
| 需求场景 | 待接入 | 后台算前后四周意向变化，模型结合原文说明经营含义；内部意向不冒充行业热度 |
| 竞品态势 | 待接入 | 模型逐条选择相关竞品依据、说明理由；资料不足不编造促销涨幅 |
| 渠道效率 | 待接入 | 后台算每笔支付订单对应投放费用及变化，模型判断；不将同期比值说成增量回报 |
| 渠道 × 商品角色矩阵 | 全期数量堆砌 | 冻结商品/SKU角色关联，计算两个等长四周窗口，模型逐格写短判断、解释和核查优先级 |
| 市场变化 | 长篇原文及空历史框 | 默认显示三条模型提炼的关联观察；发布时间与读取时间分开，当前材料不解释历史因果 |
| 渠道投入结构 | 数字缺乏承接 | 保留全统计期渠道投入结构，说明与四周比较的期间差异 |
| 查看证据 | 来源堆砌 | 判断、前后期关键数字、下一步、简明来源；原始资料保持可追溯 |

## 真实后端链路

导入记录 → 发布经营资料版本 → 冻结企业、期间、商品、渠道及事实记录 → 后台计算对比 → 大模型读取计算与原文、检索补充信息 → 大模型筛选/分析/输出 → 逐格覆盖和引用校验 → 保存任务和结果 → 页面及证据回读。

数字由后端算，大模型负责经营判断和原文筛选。整体判断必须引用本企业渠道或货盘证据，需求与效率必须分别引用对应计算，避免只汇报外部文章。模型使用短引用编号，后台逐一还原完整企业与资料版本标识；无法对应的引用会被拒绝，编号不进入经营文案。没有完成的模型结果就显示等待或失败，不用固定规则文案替代。新版资料创建后使用新事实重新计算，并有独立模型任务；旧版本和旧结果仍可回读。加载页面自动触发缺失的分析，显式更新产生新任务，重复请求复用已有任务。

原文由模型分为需求、竞品、渠道和政策；政策与标准不计入竞品来源数量。模型输出还校验整体变化方向、渠道与货盘的统计范围以及行为/订单单位。订单和净成交未分解价格时，不把金额下降解释成降价。

明确的意向、订单、金额和费用变化还会与后台前后期计算核对。模型读错增长、回落或持平时，将发现的错误汇总交回模型，最多两次有界修正，不由前端替换判断。新增市场检索失败会作为缺口返回模型，已有经营计算和已读取原文仍可继续分析；不可读取来源不能入选。

后台分别处理订单明细去重、退款扣减、费用归属、完整周和资料覆盖。行为次数与订单笔数不互除为客户转化率；未归属货盘的渠道费用不分摊；缺少资料或零基线不编造变化百分比。

原文候选按最近保存的 12 条进入本次模型审查。本次模型输入使用最多 1,500 字符的正文片段并标记是否截断，完整已抓取原文保存在后台。片段不足以支持的结论须保留缺口；这不是全网或全部历史资料的完整性证明。

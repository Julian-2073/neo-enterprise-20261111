# NEO Ontology 可操作配置中台

本次将日常入口改为经营数据输入、经营规则和三个智能体配置；原有对象类型、关联、血缘、投影、函数与运行证据保留在高级入口。原 `/demo` 继续是唯一经营前端。

## 实际操作

1. 经营数据输入支持直接填写一条记录及 CSV；共用原有13类模板、原件存储、校验、事实/主数据入库。严格关联是默认值，兼容导入保留缺失提示，不造主数据。无效批次可以修正覆盖日期或补齐关联资料后重新校验；已通过或入库的范围不可改，旧校验版本不得提交。
2. 经营规则可设置4至52个完整周的默认统计窗口、客户起始阶段、1至90天转化观察期和渠道口径。供给评价规则、安全库存、到货等业务条件使用相应数据表单输入。只提供现有注册的规则，不提供任意脚本。
3. 三个专业可设置启停、职责、补充要求和可选工具。基础业务结构及经营读取保留；专业权限和服务端外部检索开关仍有约束。Python 在真正选择专业、组装提示、提供和执行工具时消费这份配置；前端停用专业提示与服务器拒绝相同。
4. 保存草稿 → 影响预览 → 发布。规则进入之后生成的经营快照；智能体设置进入之后发起的任务。当前配置、数据版本和旧记录分开。发布数据版本不启动调查；原页面原有的自动巡检继续受服务端策略控制，本地主版关闭自动巡检。
5. 数据生成截止默认当前上海日期，统计期间仍是已结束完整周。当周输入不计入已结束统计周，需要按页面显示的期间核查。

## 接口与存储

- `GET /api/v1/ontology/platform`：读取当前企业/资料性质的配置、最近前端数据版本与版本摘要。
- `POST /api/v1/ontology/platform/drafts`：提交结构化设置及当前 `baseId`，仅管理员。
- `POST /api/v1/ontology/platform/drafts/{id}/preview`：校验并展示影响，草稿不进入运行。
- `POST /api/v1/ontology/platform/drafts/{id}/publish`：D1 原子批次比较配置头并发布。过期草稿409；同一发布重复请求回读已保存版本。
- `POST /api/v1/ontology/platform/snapshots`：从同企业同资料性质已提交事实生成前端快照，不启动付费任务。
- 数据填写继续使用现有 `ingestion-batches` 校验/提交接口。
- Drizzle 生成并检查迁移 `0010_right_deathstrike.sql`，新增企业配置版本与配置头两张表，无远端迁移。
- 快照保存 `platformConfigId`；调查保存完整 `platformConfiguration`，结果附 `platformConfigurationId`。旧快照、结果、原件不重写。

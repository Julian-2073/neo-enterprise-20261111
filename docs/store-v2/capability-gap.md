## 3. 合同层缺口（DEV02 直接前置）

| 合同 | 状态 | 说明 |
| --- | --- | --- |

| `Money` | 部分 | 统一用整数分（`server/contracts.ts`），但无金额类型与越界拒绝合同 |

| `Evidence/Case/Plan/Task` 命令 | 缺失 | 仅经营计划草稿，无 Case/Task 命令与幂等版本 |
| 审计与 outbox | 缺失 | 仅 `snapshot_created` 一条审计 |

## 4. 不可跨越的边界（实现时必须保持）

1. `day_sku` 粒度不得产出订单数、客单价、订单搭配、多活动订单去重；返回 `null` + `reason`。
2. 未知一律 `null`，不得填 0；覆盖不足不得用「0 元」代替。
3. 金额、贡献、活动结余等由确定性计算产生，LLM 不得计算金额。
4. 权限由服务端解析；模型无审批权与写回权。
5. 保留 `/workspace/store`、`/api/v1/store`、legacy 预测链路；新增只走 `/api/v2/store`。
6. 新表只追加 Drizzle migration，不改既有迁移。
7. 证据级别不得跨级宣称（E0 文档 → E6 增量）。

## 5. 阶段依赖提示

- DEV02 必须先补齐 `Scope/Availability/Money/粒度/MetricResult/命令` 合同，否则 DEV03 导入与 DEV04 计算会产生口径漂移。
- DEV04 的三项分析必须各自可独立验证；现有 `business-metrics-v1.2` 不足以覆盖 R02/R03。
- DEV05 的缺码闭环依赖 DEV02 的 Case/Task 命令与 DEV03 的不可变快照。
- DEV09 依赖 DEV08 的审批/任务边界，否则模型工具无法证明「只读」。
